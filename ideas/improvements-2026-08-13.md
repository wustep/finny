## Technical

### 1. Do not advance the Plaid cursor when a Notion write fails
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `transactionsBatch` in `convex/sync.ts` wraps each added/modified/removed write in `try/catch` that only `console.error`s, then always calls `setCursor` with `next_cursor`. The comment even says the cursor should move only after the page is fully processed — but a 400, exhausted retry, or archive failure still advances it. Plaid will not re-send those updates, so the transaction is gone from Finny forever.
- **Proposal.** Skip `setCursor` unless every in-scope record on the page succeeded (or was already mapped). On partial failure, `finishRun` as `error`, leave the cursor, retry the same page. Add a dead-letter / skip-after-N for a poison row so one bad select option cannot stall the Item forever.
- **Risks / trade-offs.** A permanently unwritable row can block the cursor; needs a visible skip path. Retrying a page whose successful creates are not yet in `notionPageMap` duplicates rows unless idea 4 lands first (or claim-then-create is in the same change).
- **Files.** `convex/sync.ts`, `convex/syncData.ts`

### 2. Treat only `PRODUCTS_NOT_SUPPORTED` as a successful investments skip
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `investmentsBatch` catches **any** throw from `investmentsTransactionsGet`, logs “investment transactions unavailable”, and `finishRun(..., status: "success")`. That also swallows `ITEM_LOGIN_REQUIRED`, rate limits, and 5xx. `finishRun` then sets `lastSyncedAt` and forces the bank connection back to `active`, so a broken Item looks healthy.
- **Proposal.** Inspect Plaid `error_code` (same path as `convex/plaidClient.ts`). Only product-unsupported / no-investment-accounts codes finish as success. Everything else finishes as error and leaves Item status alone.
- **Risks / trade-offs.** An over-narrow allowlist will error cash-only Items on every cron. Confirm sandbox vs production codes before shipping.
- **Files.** `convex/sync.ts`, `convex/plaidClient.ts`, `convex/syncData.ts`

### 3. Exclusive per-connection sync lease
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `runForConnection` only “skips if busy” for `webhook`/`cron`, via query-then-insert. `hasRecentRunningRun` looks at the latest 3 `syncRuns` and treats a run as busy only if `status === "running"` **and** `startedAt` is within 5 minutes. Two webhooks 1ms apart both proceed; manual/`initial` skip the check; a 2-year backfill routinely lasts >5 minutes, after which cron starts a second run against a live cursor. Overlap duplicates Notion pages and last-`setCursor` can skip a page of the Plaid stream.
- **Proposal.** Add a check-and-set lease on `bankConnections` (`syncLockExpiresAt` / `activeRunId`) in a **single mutation**. Apply it to every trigger. Heartbeat from each batch; `finishRun` and a timeout sweeper always release. Optionally enqueue the skipped webhook to `runAfter` when the lease drops.
- **Risks / trade-offs.** A stuck lease blocks the Item until TTL. Too-short TTL recreates overlap; too-long delays webhook catch-up.
- **Files.** `convex/sync.ts`, `convex/syncData.ts`, `convex/schema.ts`, `convex/plaid.ts`, `convex/crons.ts`

### 4. Claim-then-create for every mapped Notion page
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Creates happen, then the ID map is written later: `transactionsBatch` calls `putMapEntries` only after the whole added/modified/removed loop; `upsertMapped` is create-then-map as two steps. Crash/retry creates a second Notion row. Categories already use `claimMapEntry` + `findPageByText`; transactions, accounts, holdings, securities, and balance snapshots do not, even though those DBs have an `ID` property. `rekeyMapEntry` can also patch onto a key that already exists; `by_user_kind_provider` is not unique.
- **Proposal.** Claim-then-create for every mapped kind. Write the map before the next create. On retry, look up by `ID` before creating. Make `by_user_kind_provider` unique; make `rekeyMapEntry` merge if `toProviderId` already exists. Route securities through the same claim path as categories (`claimMapEntry` comment already says they need it).
- **Risks / trade-offs.** Extra Notion queries on the create path (rate limit). Unique-index migration fails if duplicates already exist (needs a cleanup pass).
- **Files.** `convex/sync.ts`, `convex/syncData.ts`, `convex/notionApi.ts`, `convex/schema.ts`

### 5. Upsert Plaid accounts discovered after Link
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Convex `accounts` rows are inserted only in `saveConnection` during `exchangePublicToken`. Later `accountsGet` skips any Plaid account whose id is not already in Convex. `NEW_ACCOUNTS_AVAILABLE` is unhandled. Link update-mode success only toasts “Connection repaired” — no account upsert, no status patch, no sync. A new checking account at a linked bank never appears in Finny or Notion.
- **Proposal.** After every `accountsGet` (and after update-mode Link success), upsert Plaid accounts (keep `syncEnabled` for known ids; default new ones to `false` and surface them). Handle `NEW_ACCOUNTS_AVAILABLE` like other sync webhooks. On reconnect success, set status `active` and schedule a run.
- **Risks / trade-offs.** Auto-enabling new accounts may sync credit/joint accounts the user did not want — default off is safer. Newly inserted accounts whose item cursor has already moved still miss history unless paired with idea 6.
- **Files.** `convex/sync.ts`, `convex/connections.ts`, `convex/plaid.ts`, `src/components/plaid-link.tsx`, `src/routes/plaid-oauth.tsx`, `src/routes/index.tsx`

### 6. Account sync toggles must not eat the Plaid cursor
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `inScope` drops txns for `!syncEnabled` or `date < startDate`, then `setCursor` still advances. Turning an account off and back on cannot recover skipped ids. Initial backfill with some accounts disabled permanently omits their history. `startDate` is frozen at `createDatabases`; the only escape is operator `resetAndResync`, which rebuilds everything.
- **Proposal.** For disabled accounts, still apply modified/removed to already-mapped rows (pending→posted) but skip *creates* — or set a per-account catch-up flag and use a bounded `transactions/get` when re-enabled. Persist start-date changes with an explicit cursor reset or one-shot historical pull. Document that disable is not “pause, then resume history.”
- **Risks / trade-offs.** Updating disabled accounts still burns Notion rate limit. Per-account `transactions/get` can duplicate if the ID map is wrong. Rewinding the shared item cursor re-streams other accounts.
- **Files.** `convex/sync.ts`, `convex/connections.ts`, `convex/notion.ts`, `convex/syncData.ts`, `src/routes/index.tsx`, `src/routes/notion.tsx`

### 7. Archive vanished investment transactions; always `finishRun`
- **Impact:** 🟡 med · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Cash txns use Plaid’s `removed` list; holdings archive IDs missing from the current snapshot. `investmentsBatch` only creates/updates. Canceled investment txns disappear from Plaid and stay in Notion forever. Also: if `loadContext` returns null in `transactionsBatch` / `investmentsBatch`, the handler returns **without** `finishRun`, so `syncRuns` stay `running` and feed the stale lock in idea 3.
- **Proposal.** After the last investments page, archive mapped `investmentTransaction` ids for this Item that were not seen in the full window (same pattern as holdings). Always `finishRun` on early `loadContext` failure. Key map rows by `connectionId` so a large user cannot `collect()` past query limits.
- **Risks / trade-offs.** A truncated Plaid window would archive real history — reconcile only after a complete walk, and only for this Item’s accounts. Large `seen` arrays through `scheduler.runAfter` hit argument size limits; persist seen ids instead.
- **Files.** `convex/sync.ts`, `convex/syncData.ts`, `convex/schema.ts`

## Product Features

### 8. Reconnect CTA, Notion Status, and break alerts
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Plaid `ITEM`/`ERROR` and `PENDING_EXPIRATION` already patch `bankConnections.status` + `errorCode`, but Accounts only shows a badge and hides Reconnect in a ⋯ menu. `errorCode` is never rendered. Daily cron **skips** `status === "error"` items, so the Notion Bank Connections Status stays Active. Update-mode success does not clear status or start a sync. Until the user happens to reopen the app, the Item is dead.
- **Proposal.** Error/expiring cards: show `errorCode`, primary Reconnect, short copy. On update-mode success: set `active`, schedule sync. On ITEM ERROR / PENDING_EXPIRATION: upsert the Notion Bank Connection row to Error / Pending expiration. In-app banner (email optional) on status transition. Do not skip the Status write in cron.
- **Risks / trade-offs.** Email needs a provider and can leak that a bank failed (no amounts). Aggressive prompts on transient errors. Writing Notion on webhook contends with sync for rate limit.
- **Files.** `src/routes/index.tsx`, `src/components/plaid-link.tsx`, `src/routes/plaid-oauth.tsx`, `convex/plaid.ts`, `convex/sync.ts`, `convex/syncData.ts`, `convex/connections.ts`

### 9. Guided setup + live first-sync progress
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** PLAN.md specifies sign-in → Notion → modules/start date → banks → first sync with progress. The app dumps you on Accounts; Notion is a separate page with no checklist. `DestinationCard` still says “Syncing engine arrives in the next phase” even though `createDatabases` already schedules `runForConnection` and `exchangePublicToken` kicks an `"initial"` sync. `syncRuns` has live `stats`, but the UI is a 10-row log with no remaining work and no empty-state pointing at `/notion` when banks exist without a destination.
- **Proposal.** First-run wizard matching PLAN. Drive a progress view off `syncRuns` (`running` + added/modified/removed). After DBs exist, replace the stale Destination copy. Banner on `/` when connections exist but `notionConnections.databases` is missing.
- **Risks / trade-offs.** Wizard that blocks “add another bank later”; progress that lies during a 2-year backfill at Notion’s ~3 rps. README currently documents Accounts-first — update it with the wizard.
- **Files.** `src/routes/index.tsx`, `src/routes/notion.tsx`, `src/components/app-shell.tsx`, `convex/notion.ts`, `convex/plaid.ts`, `convex/syncData.ts`

### 10. Destination as the sync control plane
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** PLAN.md Destination: target page, modules, start date, manual sync, sync history. After `databases` exist, `DestinationCard` is read-only links + Disconnect. Modules and `startDate` freeze at `createDatabases`. There is no “turn on Investments later,” no start-date change, no Sync now (that lives only on each bank card). `createDatabases` already reuses existing DB ids, so adding a module is mostly “create missing specs + schedule sync,” but no UI calls it.
- **Proposal.** Live destination: workspace, parent page, module toggles (create missing DBs, don’t delete), start-date with an explicit “re-backfill from this date” (rewind cursors — don’t silently change the filter), Sync now (all connections), recent runs. Keep Disconnect, with copy that it stops writes and leaves Notion data.
- **Risks / trade-offs.** Changing `startDate` without cursor reset does nothing useful. Turning a module off should not archive those DBs. Adding Investments on a cash-only Item hits `PRODUCTS_NOT_SUPPORTED` (idea 2). Map-to-existing stays deferred.
- **Files.** `src/routes/notion.tsx`, `convex/notion.ts`, `convex/notionSchemas.ts`, `convex/sync.ts`, `convex/syncData.ts`

### 11. Reconnect Notion without recreating databases
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Banks have update-mode; Notion does not. `notion.disconnect` deletes the whole `notionConnections` row, including `databases`. Reconnect hits SetupCard and `createDatabases` (fresh DBs unless ids were still on the row). `saveConnection` already **keeps** `databases` when the workspace id matches — but only if you OAuth without disconnecting first. Expired/revoked integration → syncs error forever, or the user Disconnects and duplicates every DB.
- **Proposal.** Destination “Reconnect Notion” → existing `startOAuth` without deleting the row. On 401/403 from Notion during sync, mark destination unhealthy and prompt reauth. Disconnect: optional token revoke, delete Convex row, leave pages in Notion. Never create a second set of DBs when ids still resolve.
- **Risks / trade-offs.** Reauth to a **different** workspace already clears `databases` — make that failure loud. Stale DB ids after the user deletes DBs in Notion still 404 (needs idea 13’s rebuild, not a third create).
- **Files.** `src/routes/notion.tsx`, `convex/notion.ts`, `convex/sync.ts`, `convex/http.ts`

### 12. Show run errors and expose Reset & resync in the app
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `connections.recentRuns` already returns `error`; `SyncHistory` never renders it. Per-row failures are `console.error` + continue, so a run can be `success` with missing rows. `resetAndResync` exists for humans and is not in the UI. Crashed actions leave `status: "running"` forever. Users who trash a database or hit a partial backfill have no self-serve repair.
- **Proposal.** Expand run rows: `error` text, duration, added/modified/removed even on failure, stuck-running → failed after timeout. Count skipped-on-exception in `stats`. Destination/Settings: “Reset mappings & resync” with the existing warning (delete Notion rows or accept duplicates). Do not expose `resetAndResyncByEmail`.
- **Risks / trade-offs.** Raw Notion/Plaid errors can include page ids. One-click reset without deleting Notion rows duplicates the ledger. Timeout-failing a still-working long backfill causes overlapping runs (idea 3).
- **Files.** `src/routes/index.tsx`, `src/routes/notion.tsx`, `src/routes/settings.tsx`, `convex/sync.ts`, `convex/syncData.ts`, `convex/connections.ts`

### 13. Pass-through transaction rules (categorize / rename / hide)
- **Impact:** 🔴 high · **Effort:** L · **Status:** ✅ accepted
- **Problem.** A rules engine is what makes a Notion ledger usable; PLAN.md names it phase 6 / deferred. There is no `rules` table and no Rules route. Sync writes PFC category and cleaned merchant with no user override. Edits to Finny-owned properties in Notion get overwritten on the next `updatePage`. Hide is impossible without storing amounts: evaluation must happen in the sync pass-through.
- **Proposal.** `rules` config only (merchant/summary/account/day/amount conditions; outcomes: set category, rename title, skip/archive). Apply in `transactionsBatch` before create/update. Priority-ordered; document that Notion edits to Finny-owned properties lose. Hide = don’t create, or archive + drop map entry so later syncs don’t resurrect.
- **Risks / trade-offs.** Amount conditions already see Plaid payloads in memory, but logs that echo merchants fight the “we don’t store financial data” story. Regex + hide can drop real spend with no in-app preview. Large L that delays reconnect/onboarding polish.
- **Files.** `convex/schema.ts`, `convex/sync.ts`, `convex/rules.ts` (new), `src/routes/` (Rules page), `src/components/app-shell.tsx`

### 14. Settings: disconnect everything and delete account
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** PLAN.md Settings: “profile, disconnect everything.” `src/routes/settings.tsx` is email + Sign out. Policy says bank remove revokes Plaid immediately, Notion disconnect drops the token, and **account deletion is email-only within 30 days**. `plaid.removeConnection` and `notion.disconnect` exist per-surface; nothing cascades user row, `notionPageMap`, `syncRuns`, or `accessGrantedAt`. A personal-finance app that stores Plaid access tokens cannot make “email Stephen” the only off-ramp.
- **Proposal.** Settings: Disconnect all banks, Disconnect Notion, Delete my account (all of the above + delete map/runs/oauth states/user). Confirm copy: Notion pages stay; Finny tokens go. Match `/policy` so the 30-day email path is backup, not the product.
- **Risks / trade-offs.** Deleting `notionPageMap` while leaving Notion pages is correct for teardown and fatal if they sign back in and sync again (duplicates). Plaid production Item slots are not refunded on delete — say so in the confirm dialog. Incomplete delete that leaves access tokens is worse than no button.
- **Files.** `src/routes/settings.tsx`, `src/routes/policy.tsx`, `convex/plaid.ts`, `convex/notion.ts`, `convex/connections.ts`, `convex/users.ts`, `convex/syncData.ts`

## DevEx

### 15. GitHub Actions CI that typechecks Convex and runs oxlint
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** There is no `.github/`. The only automated gate is Vercel `npm run build` (`tsc -b && vite build`). Root `tsconfig.json` references only `src` and `vite.config.ts`; `convex/tsconfig.json` is orphaned, so the sync engine, webhook JWT verify, and schema are never typechecked on PR. `npm run lint` never runs remotely.
- **Proposal.** `.github/workflows/ci.yml` on PR/push: `npm ci`, `oxlint`, `tsc -b`, `tsc -p convex`. Add `"typecheck": "tsc -b && tsc -p convex"`. Ignore `convex/_generated/**` and `src/routeTree.gen.ts` in oxlint. Do not require a Convex deploy token — `_generated/` is already committed.
- **Risks / trade-offs.** First CI run may fail on existing Convex TS issues Vite never saw; fix those rather than weakening `strict`. Does not prove the backend deployed.
- **Files.** `.github/workflows/ci.yml` (new), `package.json`, `tsconfig.json`, `.oxlintrc.json`

### 16. Extract and unit-test money / sign mappers
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Amount conventions live as untested helpers at the bottom of 1100+ line `"use node"` `convex/sync.ts`: Plaid outflows flipped negative for Notion, cash-type investment sign flip, credit balances kept positive, APR `/ 100`. A one-character sign flip silently writes wrong dollars. PLAN.md still documents Transactions as `Summary` / `Is Pending?` / `Merchant Name`, but `notionSchemas.ts` uses `Name`, `Pending`, `Original Description` — agents following PLAN.md generate the wrong keys.
- **Proposal.** Move the mappers into `convex/syncMappers.ts` with no Plaid client imports. Add `convex/syncMappers.test.ts` (plain vitest) for outflow −$12.34, pending flag, cash deposit vs buy, null APR, credit current-balance positive. Point PLAN.md at `notionSchemas.ts` as the live schema.
- **Risks / trade-offs.** Must not change mapper output (Notion property names are a live contract).
- **Files.** `convex/sync.ts`, `convex/syncMappers.ts` (new), `convex/syncMappers.test.ts` (new), `PLAN.md`

### 17. convex-test for ID-map claims, access gate, and ownership
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** Zero test files. `.claude/skills/convex-test` is unused. The risky logic is Convex mutations: `claimMapEntry` timeout/reclaim, `rekeyMapEntry` when the destination already exists, `hasRecentRunningRun` window, `access.attemptRedeem` 3-strikes IP ban, `saveConnection` cross-user throw, `consumeOauthState` one-time consume. A regression writes duplicate Notion pages or unlocks the access password.
- **Proposal.** Install `convex-test` + vitest + `@edge-runtime/vm`. Tests for claim ready/pending/timeout, rekey collision, access ban, cross-user `saveConnection`, oauth consume. Do not try to in-process-test `"use node"` `sync.ts` / `handleWebhook`. Wire `npm test` into the CI job from idea 15.
- **Risks / trade-offs.** Wrong vitest/edge-runtime config fails with `import.meta.glob is not a function`. Internal mutations need `t.mutation(internal.…)` not public `api`.
- **Files.** `package.json`, `vitest.config.ts` (new), `convex/syncData.test.ts`, `convex/access.test.ts`, `convex/connections.test.ts`, `convex/notion.test.ts` (new)

### 18. Typed Convex env and a complete `.env.example`
- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** All secrets are untyped `process.env.*`. `.env.example` only lists `VITE_CONVEX_URL` plus Plaid/Notion stubs labeled “phase 2/3”. It omits `ACCESS_PASSWORD`, `TEST_LOGIN_SECRET`, `PLAID_SANDBOX_SECRET`, `APP_ORIGINS`. Missing `ACCESS_PASSWORD` is a 503 after Google sign-in; missing `PLAID_SANDBOX_SECRET` silently burns production Items from localhost.
- **Proposal.** Add `convex/convex.config.ts` with `defineApp({ env: … })` for every Convex-side key. Read via generated `env`. Rewrite `.env.example` as a checklist (Vite keys vs `npx convex env set`), no “phase N”. Keep values blank.
- **Risks / trade-offs.** Optional keys (`PLAID_SANDBOX_SECRET`, `TEST_LOGIN_SECRET`, `APP_ORIGINS`) must stay optional or local-only flows break. Do not put real secrets in `.env.example`.
- **Files.** `convex/convex.config.ts` (new), `.env.example`, `README.md`, `convex/access.ts`, `convex/auth.ts`, `convex/plaidClient.ts`, `convex/plaid.ts`, `convex/notion.ts`, `convex/origins.ts`, `convex/users.ts`, `convex/http.ts`

### 20. One-command local dev (Convex + Vite)
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `package.json` scripts are only `dev` (vite), `build`, `lint`, `preview`. README setup is eight steps and two long-lived processes: `npx convex dev` then `npm run dev` on pinned port 3466. There is no `typecheck`, `test`, or `convex:dev`.
- **Proposal.** `"dev": "concurrently … convex dev + vite"`, keep `"dev:app": "vite"` and `"convex:dev": "convex dev"` as escape hatches. Collapse README step 8 to `npm run dev` → http://localhost:3466. Add `typecheck` / `test` scripts from ideas 15–17.
- **Risks / trade-offs.** `convex dev` is interactive on first login; a combined script can look hung. `strictPort: true` means a leftover Vite kills the whole group.
- **Files.** `package.json`, `README.md`
